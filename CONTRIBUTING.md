# Contributing

[Current state](CURRENT.md) · [Quality contract](QUALITY.md) · [Repository hub](docs/INDEX.md)

Use `python3 tools/project.py context <route>` before changes. Keep claims tied to evidence and separate research, qualified implementations and physical measurements.

## Complete a change

Update current facts in `project.json`, rationale in decisions and evidence in original records. Classify modules and maintain routes. Run `refresh`, `audit`, `check` and applicable tests; tooling changes also run the Git/recovery suite. Review staged content. Preserve failures, identities, parents, hashes and scientific requirements. New batches require inventory, integrity verification and a privately restored backup; report gaps as incomplete.

## Local setup

[Setup and gate commands](docs/maintaining-repository.md#local-setup). Install pinned dependencies and all four hooks in every new/restored checkout. Hooks never download, rewrite or stage files.

## Documenting a hardware project

[Build and release conventions](docs/documenting-hardware.md). Add useful revision-matched sources, BOM/sourcing, fabrication, assembly, calibration and measured validation when available.

## Private evidence

[Capture and restore procedure](docs/maintaining-repository.md#private-evidence). Keep original bytes and licence notices; follow [licensing](LICENSE). No purchasing, contact, payment, licence acceptance or publication is authorized here.
