# Prompt 2 — Strengthen qualification and evidence states

Read [the shared execution contract](research-workflow.md) and use the `qualification` context route. Inspect current reports and original evidence before extending work; later stages may already have supplied outputs or preserved corrections.

Close the most important gaps in the existing test framework before using it to rank real architectures. Inspect Prompt 1's device-model evidence and work around missing coverage without pretending it is complete.

1. Implement declared loop-injection interfaces and validated return-ratio/Nyquist analysis for relevant feedback, servo, bootstrap and common-mode loops. Preserve the operating point and loading. Use independent analytical controls, including a deliberately unstable control. Document sign conventions, applicable assumptions and treatment of interacting loops. HF peaking or phase margin from an incorrectly opened loop must not establish stability.
2. Add realistic device power/rating checks and supported clipping/headroom analyses. Distinguish manufacturer absolute ratings, modeled behavior and missing safe-operating-area evidence. Keep right-censored headroom as a lower bound; never convert it into a measured maximum SPL.
3. Extend environmental evaluation to include noise and distortion at documented P48, temperature, cable/preamp, capsule, passive and semiconductor corners. Use a staged, explicitly recorded coverage policy to manage computation. Untested combinations remain missing coverage.
4. Separate capsule/interface uncertainty scenarios from evidence-backed manufacturing variation. Include completed failing specimens in metric percentiles and worst-case results. Count simulation errors in failure denominators and expose missing numeric metrics. Preserve weighting, bandwidth, units and noise-contribution closure.
5. Introduce separate derived evidence states for nominal feasibility, simulation robustness, procurement readiness, patent-screening state, prototype readiness and physical qualification. Preserve existing production eligibility and its physical-evidence requirement. Prototype readiness needs safe capsule-bias evidence, applicable device limits, a robustness record, a realized standard-parts BOM with qualification at its actual values/tolerances and verified small-quantity Germany sourcing/delivered-cost evidence, the applicable dated patent review with no unresolved potentially blocking claim hold, and a measurement plan; it must not require measurements from a prototype that has not yet been built. Evidence labels must resolve to reviewable artifacts, not just unchecked metadata strings. Procurement uncertainty must not silently change a physical test result.
6. Record simulator/model/source/specification fingerprints and numerical uncertainty. Add meaningful regressions for the new failure paths and analytical controls. Never treat a warning, convergence failure, missing model behavior or unsupported analysis as a pass.

Deliver executable framework changes, evidence/status documentation, preserved control results, a coverage matrix and `research/devices/qualification-upgrade-report.md`. Any proposed engineering acceptance threshold not already specified must be documented as a separate specification proposal with evidence; do not silently change the specification lock to complete this task.

Run `./run verify` and repeat the nominal and numerically proposed infrastructure fixtures under one stable source cohort. Preserve the earlier records and explain changes in results. The ideal fixture must remain ineligible even if individual checks pass. Finish by identifying which architecture classes the strengthened suite can validly evaluate and which need additional protocols.
