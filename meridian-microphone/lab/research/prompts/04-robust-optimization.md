# Prompt 4 — Optimize independently and test robustness

Work in `meridian-microphone/lab`, relative to the repository root, on the M100 Meridian MIC-34-M/MIC-34-C research project using the Arienne Audio Flat K47 Cardioid/Omni K47FRB under P48.

Read [the shared execution contract](research-workflow.md) and use the `optimization` context route. Inspect current reports and original evidence before extending work; later stages may already have supplied outputs or preserved corrections.

Preserve the hierarchy: physics/measurements → SPICE → automated tests → numerical optimization → engineering reasoning → LLM intuition. Work autonomously, create files and run applicable checks. Preserve failed experiments, raw data, source snapshots, seeds and parent relationships. Do not relax thresholds, silently narrow uncertainty ranges, hand-select devices, conceal trimming, purchase parts or contact suppliers. Unknown safe capsule polarization is not a simulated hardware rating. Freeze shared sources before running evaluations. No production topology or PCB is to be selected in this task.

Numerically optimize the viable candidates from the first diverse batch. Audit prerequisites first: do not rank candidates using missing noise, unvalidated models or incompatible analysis protocols.

1. Extend the existing nominal optimizer to support documented worst-case or high-percentile objectives where the evidence permits them. Separate hard acceptance constraints from performance axes. Keep noise, distortion, headroom, loading, balance, drive, current and complexity available as separate objectives; do not introduce an arbitrary weighted winner score.
2. Declare topology-specific continuous parameters and physically justified bounds: passive values, currents, bias, compensation and servo time constants where appropriate. The LLM identifies parameters and structural hypotheses; numerical algorithms determine continuous values. Any polarization search remains simulation-only while the capsule's safe range is unknown.
3. Give each family a comparable initial simulation budget, explicitly recorded before its run. Use staged inexpensive feasibility tests followed by higher-cost analyses. Report evaluations, failures, runtime, seeds and optimizer termination. Budget exhaustion is not convergence or global optimality. Allocate further effort using the 50/25/15/10 research policy without eliminating distinct families.
4. Evaluate evidence-backed coupled semiconductor corners, passive tolerances and capsule/interface uncertainty. Use probability distributions only when their provenance supports that interpretation; otherwise report scenario robustness or bounded stress results. Never report a manufacturer's guaranteed bounds as a measured population distribution.
5. Validate optimized proposals on additional documented corners and independent random seeds not used by the optimizer. Keep all finite adverse specimens in percentile/worst-case summaries and all failed analyses in denominators. Report confidence intervals and sample counts; a small successful run cannot establish 99.9% production yield.
6. Run the complete applicable suite before advancing a proposal's evidence state. Preserve source/model/specification cohorts and parent comparisons. Missing checks remain incomplete. Retain the best demonstrated representative within each architectural niche even when another family performs better globally.

For each promising continuous proposal, create a traceable realized-BOM child using obtainable nominal values, documented component grades and actual device variants. Numerically explore feasible preferred-value combinations where useful. Include tolerance, parasitic, leakage, noise and temperature effects; repeat the complete applicable suite and report the performance change from the continuous parent. A rounded value or nominally equivalent substitute is not qualified until evaluated. Keep both records and their exact models.

Carry forward each candidate’s patent-screening state and affected-feature holds. Revisit claim mappings after structural changes or implementation substitutions; do not infer a design-around from improved novelty or different numerical values. Keep engineering rankings and patent-gate evidence separate.

Track intended-quantity delivered German BOM cost and procurement readiness as separate comparison axes, using dated basket-level sourcing evidence. Do not optimize against hypothetical bulk/reel prices or unknown shipping treated as zero. If a substituted part or alternate sourcing-dependent implementation changes electrical behavior, preserve a new implementation record and repeat affected qualification. Retain theoretical results while clearly separating their sourcing gaps from physical performance. No numerical spending cap or arbitrary cost/performance score is authorized.

If a topology has no feasible value region, document the limiting mechanism. Use the Inventor/Engineer process to make a small number of explicitly budgeted structural child experiments, rather than endlessly tuning resistors. Preserve the defining hypothesis and failure history; do not change thresholds to rescue it.

Deliver updated optimization code, immutable proposal/trial records, full-suite re-evaluations, corrected archive/Pareto views and `research/architectures/optimization/robust-optimization-report.md`. Distinguish nominal feasibility, tested scenario robustness, statistically supported manufacturing evidence and physical qualification. Do not promote simulation-only candidates into the physical-qualified production front.

Run meaningful optimizer/robustness regressions and `./run verify` after implementation changes. Finish with family-specific improvements, regressions, uncertainty-sensitive rankings and the most informative next experiments, rather than one declared production winner.
