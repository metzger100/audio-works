# Scoped evidence reading

The engineering context loads project authority, the complete scientific contract, every acceptance specification and the source-register entry. Follow the relevant rows before affected work. Extra required scientific evidence has no reading ceiling; indexes are routes to evidence, never substitutes for it.

| Affected work | Required additional reading |
| --- | --- |
| Any scientific claim | Relevant entries in [source groups](sources/INDEX.md), exact current findings, original conditions, hashes, failures and parents |
| Device/model changes | [Library instructions](../models/semiconductor/README.md), exact registry/reference/corner records and [device findings](devices/INDEX.md) |
| Concepts, topology or optimization | [Inventor/Engineer protocol](memory/roles.md), affected hypotheses, [candidate conditions](../candidates/README.md), families and bounds |
| Qualification or interpretation | Relevant [discoveries](memory/discoveries.md), [failed approaches](memory/rejected-ideas.md), full metric suite, original cohort and [focused tests](architectures/focused-hypotheses-001.md) |
| BOMs, cost or sourcing | [Germany contract](procurement/germany.md), exact dated part/basket records; procurement state stays separate |
| Implementation features or release holds | [Patent track](patents/README.md), candidate/version mappings and dated official-status evidence |
| New results or verification | [Evidence storage](../results/README.md), inventory and private recovery procedure |

Use [research subjects](README.md) to find the smallest relevant evidence set. Read original source groups when relying on their claims; update their existing identities rather than starting parallel registers.
